## 1. Executive Summary

Root commit `0b805a8` resolved several earlier foundation issues: UTF-8 JSON request decoding, omitted-`null` `parentId` on root comments, server-confirmed comment creation, typed `ArticleDetail` decoding, native TipTap block rendering (`paragraph`, `heading`, `bulletList`, `orderedList`, `blockquote`, `codeBlock`, `horizontalRule`, `image`), multi-image lightbox viewing, `media_kit` video playback, reaction/vote race guards, cache invalidation on session changes, and the custom Discord vector icon.

However, comparing `0b805a8` directly against the authoritative monorepo (`ab23799bf66ecec2176b89fa0c7e1151bf5782d3`) reveals **critical contract mismatches, schema mapping bugs, and false-success/simulated UI paths** that block production readiness:

1. **Nested Comment Replies Fail on Production (`400 COMMENT_REPLY_DEPTH`):** The backend (`apps/api/src/modules/articles.ts:305-308`) enforces 1-level nesting (`parent.parentId` must be `null`). Web (`apps/web/components/social/comments-panel.tsx:94,130`) flattens replies-to-replies to `parentId: parent.parentId ?? parent.id` and prefills `@username `. Native (`lib/src/features/thread/presentation/thread_comments.dart:47,215-218`) sends the child comment's ID as `parentId`, causing every reply to a reply to fail with HTTP 400.
2. **Feedback Modal Fails 100% of Live Requests While Reporting Success:** ` FeedbackSubmitBodySchema` (`packages/contracts/src/feedback.ts:14-21`) requires `clientSubmissionId: t.String({ format: "uuid" })` and `detail: t.String({ minLength: 20, maxLength: 4000 })`. Native (`lib/src/app/app_router.dart:663-667,765-787`) prompts for "minimum 10 characters", sends `'clientSubmissionId': 'flutter-${DateTime.now().millisecondsSinceEpoch}'` (invalid UUID), catches and swallows the resulting HTTP 400 in `catch (_) {}`, and unconditionally displays `"Đã ghi nhận phản hồi!"`.
3. **Post Report Action Is a Fake Local Toast:** Selecting `Báo cáo bài viết` in `VnlfPostCard` (`lib/src/design_system/components/vnlf_post_card.dart:424-425,621-627`) shows a SnackBar (`'Đã ghi nhận yêu cầu báo cáo bài viết.'`) without calling `POST /api/v1/reports`.
4. **Notifications Modal Is Hardcoded:** `_showNotificationsModal` (`lib/src/app/app_router.dart:807-952`) renders a static `"Welcome to VNLF Social!"` item and never calls `GET /api/v1/notifications`, `POST /api/v1/notifications/seen`, or `POST /api/v1/notifications/read`.
5. **Rich Content, Image Gallery, and Video Schema Mapping Bugs:** Inline `ARTICLE` images lose `width`/`height`/`layout` and are cropped to `16:9`; empty-string `attrs.assetId` (`""`) clobbers `attrs.src`; `VnlfMediaGallery` mixes videos and images in the same 2-column grid instead of rendering videos full-width above images; `PROCESSING`/`FAILED` video attachments lose their `state` and render a dead play button; `durationMs` is parsed in `FeedAttachmentDto` but dropped in `post_mapper.dart`; and `PollDto`, `LinkPreview`, bare URL auto-linking, and `#hashtag` / `@mention` linking are unimplemented.
6. **Simulated Screens in `0b805a8` & Partial Surviving Worktrees:** Channels, Voice, Search, and Leaderboard Monthly/All-time are still sample/fixture-backed in `0b805a8`. Partial live implementations exist in `vnlf-channels-live`, `vnlf-search-live`, and `vnlf-voice-live`, each requiring specific contract fixes before merge.

### 3.2 Upstream Rich Content, Image Gallery & Video Schema Mapping Audit

Careful comparison of `packages/contracts/src/{articles,social}.ts`, `apps/api/src/lib/article-content.ts`, `apps/api/src/modules/articles.ts`, and `apps/web/components/social/{article-renderer,post-content,media-gallery,video-player,article-image-node}.tsx` against the native decoders and widgets revealed **seven concrete mapping and rendering bugs**:

1. **Inline `ARTICLE` Images Lose Dimensions/Layout and Crop to 16:9 (`lib/src/data/feed_dto.dart:67-96`, `lib/src/design_system/components/vnlf_rich_content.dart:191-222`):**
   - Upstream `ArticleDetailDto.assets` (`packages/contracts/src/social.ts:95`) is `Array<AssetDto>` containing `{ id, url, mime, size, width, height }`, and TipTap `image` nodes carry `attrs: { assetId, src, alt, caption, layout: "normal" | "wide" | "full" }` (`apps/web/components/social/article-renderer.tsx:31-35`).
   - Native `_hydrateDoc` (`feed_dto.dart:70-76`) maps `assets` to `Map<String, String>` (`id -> url`), discarding `width` and `height`. Then `_ImageBlock` (`vnlf_rich_content.dart:201-208`) creates `PostMediaData(url: url!, alt: ...)` with `width: null, height: null`. Because `PostMediaData.aspectRatio` (`vnlf_models.dart:159-162`) defaults to `16 / 9`, `VnlfMediaGallery` forces every inline article image into a `16:9` box with `BoxFit.cover`, cropping portrait diagrams and screenshots. `attrs.layout` (`normal`/`wide`/`full`) is also ignored.
2. **Empty-String `attrs.assetId` Clobbers Valid `attrs.src` (`lib/src/data/feed_dto.dart:83-85`):**
   - TipTap's `ArticleImage` node defines `assetId: { default: "" }` (`apps/web/components/social/article-image-node.tsx:20`).
   - In `feed_dto.dart:84`:
     ```dart
     if (attrs['assetId'] is String) 'src': assets[attrs['assetId']] ?? '',
     ```
     When an inline image node has `assetId: ""` and a valid direct `src` URL, `attrs['assetId'] is String` evaluates to `true` and overwrites `src` with `''`, causing `_ImageBlock` to fall back to plain alt text instead of rendering the image. Fix: check `attrs['assetId'] is String && (attrs['assetId'] as String).isNotEmpty`.
3. **Mixed Video + Image Attachments & Multi-Image Aspect Ratio Cropping (`lib/src/design_system/components/vnlf_media_gallery.dart:17-58` vs `apps/web/components/social/media-gallery.tsx:31-47`):**
   - Upstream `MediaGallery` (`media-gallery.tsx:31-32,47`) splits `items` into `videos = items.filter(item => item.url && isVideo(item) && !item.state)` and `usable = items.filter(image => image.url && !isVideo(image))`. It renders each `<PostVideo>` full-width at its natural `width / height` aspect ratio above a separate `1|2|3|4`-item image grid, and single images use `object-fit: contain` without artificial cropping (`docs/18-developer-ai-handoff.md §5.4`).
   - Native `VnlfMediaGallery` puts videos and images in the same `Wrap`; when a post has 1 video + 1 image (`items.length == 2`), the video is squeezed into a half-width square column, and single images have their aspect ratio clamped to `[0.5, 2.4]` with `BoxFit.cover`.
4. **Unready Video Attachments (`PROCESSING` / `FAILED`) Render a Dead Play Button (`apps/api/src/modules/articles.ts:32-36`, `packages/contracts/src/social.ts:19-21` vs `lib/src/data/feed_dto.dart:19-32`, `lib/src/design_system/components/vnlf_video.dart:45-47`):**
   - For the post author, `articleDto` includes `PENDING`/`FAILED` video assets in `attachments[]` with `url: null`, `state: "PROCESSING" | "FAILED"`, `posterUrl`, and `error`. Web (`media-gallery.tsx:32,41-46`) renders a dedicated status banner (`Đang xử lý video...` / error message).
   - Native `FeedAttachmentDto` ignores `state` and `error`, converts `url: null` to `""`, and passes it to `VnlfVideo`, which renders a play button that silently does nothing when tapped (`if (_loading || externalWebUri(widget.media.url) == null) return;`).
5. **Video Playback Semantics & Dropped `durationMs` (`apps/web/components/social/video-player.tsx` vs `lib/src/features/feed/presentation/post_mapper.dart:16-24`, `lib/src/design_system/components/vnlf_video.dart`):**
   - `FeedAttachmentDto` parses `durationMs` (`feed_dto.dart:29`), but `post_mapper.dart:16-24` drops it (`PostMediaData` has no `durationMs` field).
   - Web `VideoPlayer` (`video-player.tsx:12-13,26-41`) autoplays muted in a loop (`loop`) when `>= 60%` visible in the viewport (unless `reduceMotion` or `saveData` is enabled), pauses when scrolled out of view, and dispatches `vnlf:video-play` so unmuting/playing one video pauses others. Native `VnlfVideo` requires manual click-to-load, does not loop, does not pause when scrolled off-screen, and allows multiple simultaneous unmuted videos.
6. **Unlinked Bare URLs, `#hashtags`, `@mentions`, and `mailto:` Links (`apps/api/src/lib/article-content.ts:15-19`, `apps/web/components/social/{article-renderer,post-content,mention-text}.tsx` vs `lib/src/design_system/components/vnlf_rich_content.dart`, `lib/src/core/external_uri.dart`):**
   - Web auto-links bare `http(s)://` URLs inside plain text nodes (`contentLinks`), links `#hashtags` matching `article.tagSlugs` in `POST` bodies to `/t/:slug` (`post-content.tsx:12-15`), links `@mentions` to `/u/:username` (`mention-text.tsx`), and allows `mailto:` in explicit link marks (`article-renderer.tsx:45`).
   - Native `VnlfRichContent` only links explicit TipTap `link` marks with `http`/`https` (`external_uri.dart` rejects `mailto:`), and `VnlfPostCard` renders plain `Text` for post paragraphs without auto-linking URLs, `#hashtags`, or `@mentions`.
7. **Missing `poll`, `link-preview`, and `ARTICLE` Lead/Read-Time Parity (`packages/contracts/src/social.ts:91`, `apps/web/components/social/views/{feed-views,misc-views}.tsx` vs `lib/src/data/feed_dto.dart`, `lib/src/design_system/components/vnlf_post_card.dart`):**
   - `ArticleDtoSchema` includes `poll: PollDto | null` (`social.ts:91`). Web renders `<ArticlePoll>` (`POST /api/v1/polls/:id/vote`, `DELETE /api/v1/polls/:id/vote`) and, for text posts with a URL and no media/poll, `<ChatLinkPreview>` (`GET /api/v1/link-preview?url=`). Native ignores `poll` and link previews.
   - On `ARTICLE` cards in feed (`feed-views.tsx:125`), web suppresses `excerpt` when `excerpt === title`; on `ARTICLE` detail (`misc-views.tsx:61-64`), web renders an `Article` badge, read time (`Math.max(2, Math.ceil(words / 220)) phút đọc`), `title`, and `excerpt` lead above the rich `contentJson`. Native `VnlfPostCard` (`vnlf_post_card.dart:192-215`) renders both `title` and `paragraphs[0]` even when identical and omits the `Article` badge and read time.

1. **P0 — Fix Silent Write Failures & False-Success UI (`0b805a8`):**
   - **Comment reply-to-reply (`thread_comments.dart`, `vnlf_comment_tree.dart`):** Flatten `parentId` to the root comment ID when replying to a nested reply and prefill `@username `; generate and reuse a UUID `clientCommentId` per draft.
   - **Feedback submission (`app_router.dart:764-787`):** Send a valid UUID v4 `clientSubmissionId`, enforce `minLength: 20` on `detail`, pass `kind: tabIndex == 0 ? 'FEEDBACK' : 'BUG'` and the active route as `pagePath`, and remove the silent `catch (_) {}` so HTTP errors are shown honestly.
   - **Post report (`vnlf_post_card.dart:424-425,621-627`):** Replace the fake report SnackBar with a dialog wired to `POST /api/v1/reports`.
2. **P0 — Fix Rich Content, Image Gallery & Video Schema Mappings:**
   - Preserve `width` and `height` from `ArticleDetailDto.assets` in `feed_dto.dart`, guard `attrs['assetId']` against empty string `""`, and render inline `ARTICLE` images at their natural aspect ratio (`layout: normal | wide | full`).
   - Split video attachments from image grids in `VnlfMediaGallery`, preserve `state` (`PROCESSING` / `FAILED`), `error`, and `durationMs` through `FeedAttachmentDto` -> `PostMediaData`, and render processing/error banners instead of dead play buttons.
   - Auto-link bare `http(s)://` URLs, `#hashtags`, `@mentions`, and `mailto:` links in post/article text, and deduplicate `title` vs `excerpt` on `ARTICLE` cards.
3. **P1 — Complete Comment & Thread Parity:**
   - Parse `pinned`, `canPin`, `likeCount`, `viewerLiked`, `editedAt`, `attachments`, `gif`, and `mentions` in `comments_repository.dart`.
   - Sort root comments with `pinned` first (`comments_providers.dart`) and wire `PUT /api/v1/comments/:id/vote`, `PATCH /api/v1/comments/:id`, `DELETE /api/v1/comments/:id`, and `PUT /api/v1/articles/:id/pinned-comment`.
